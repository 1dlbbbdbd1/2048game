## 修复敲击模式（Smash Mode）两个 Bug

**文件**：`js/app.js`

### Bug 1：点不到方块 / 消不掉目标方块
- **原因**：`updateTilePosition()` 只更新了 DOM 元素的 CSS 位置，没有同步更新 `el.dataset.row/col`，导致方块移动后点击时读取的是旧坐标，从 `game.grid[r][c]` 找不到正确方块。
- **修复**：在 `updateTilePosition` 中追加 `el.dataset.row = r; el.dataset.col = c;`

### Bug 2：消除一个后不自动退出敲击模式
- **原因**：`smashTile` 执行成功后没有调用 `toggleSmashMode()` 关闭模式。
- **修复**：在消除动画结束的回调（setTimeout 300ms）和 else 分支中，均加入 `if (smashMode) toggleSmashMode();`

另：顺带补了 `syncBoard()` 调用，确保消除后新格子能正确渲染。

## 新增三大功能（大重构）

**改动文件**：game.js / storage.js / index.html / style.css / app.js 全部修改

### 功能1: 交换（Swap）— 蓝色
- 两次点击选两个**有值**方块交换位置（不能选空位）
- 扣分 = floor(棋盘总分 × multiplier × accum / 100)

### 功能2: 清除（Clear）— 橙色
- 点击按钮 → 弹出确认框（显示将清除的方块数和扣分） → 确定/取消
- 扣分 = floor(被清除总值 × multiplier × accum / 100)
- 无2/4方块或分数不足时在提示栏显示原因，不弹框

- 点击 ≤1024 方块翻倍（如2→4, 512→1024）
- 扣分 = floor(目标值 × multiplier × accum / 100)

### 架构改造要点
- **统一模式管理**：`currentMode` + `modeState` 四种互斥切换（smash/swap/clear/double）
- **统一代价系统**：`canUse/getCost/applyCost`，每个功能独立配置 free/cost/limit 三种模式
- **UI布局调整**：撤销+4功能按钮移到棋盘下方 `.action-bar` 工具栏
- **设置页选项卡**：敲击/交换/清除/翻倍四个Tab，每个Tab内独立的模式选择+参数
- **所有功能用一次自动退出**；Escape键退出任何特殊模式

## 第三轮修复（3个核心Bug）

### Bug 1: 扣分不生效 + 清除预演破坏grid一致性（根本原因）
- **根因**：`showClearConfirm()` 调用 `game.clearTiles()` 做预演 → 从grid移除2/4方块 → 恢复时用 `{value, r, c}` 重建（**丢失 `.el` DOM引用**）→ 导致：
  - 原DOM元素成为孤儿节点（UI尸体），`renderMove()`不会清理
  - 后续 `executeClear()` 再调 `clearTiles()` 返回的 `el: undefined`，动画和DOM清理全部跳过
  - `syncBoard()` 虽然最终会重建，但中间状态不一致导致其他功能判断异常
- **修复**：`showClearConfirm()` 改为**纯扫描计数**，不调用 `clearTiles()`，完全不修改grid
- **额外改进**：扣分时分数显示红色闪烁动画（`.score-deduct` + `@keyframes score-flash`）

### Bug 2: 交换/翻倍禁止对2和4使用
- **交换模式**：两次点击都要求 `tile.value >= 8`（2和4不可选，点错有错误音）
- **翻倍模式**：要求 `8 <= tile.value <= 1024`（原为 `value > 1024` 才拒绝，允许了2和4）
- **按钮可用性联动更新**：
  - `hasDoubleableTile()`: 改为检查 `value >= 8 && value <= 1024`
  - 新增 `countSwappableTiles()`: 统计值≥8的方块数（交换需要≥2个才启用按钮）
  - `estimateMinCost('double')`: 最小预估代价从值2改为8

### Bug 3: UI尸体根除
- 通过Bug1的修复（预演不再mutate grid）彻底解决
- 确认框现在显示具体清除数量：`将清除棋盘上 N 个方块（所有 2 和 4）`

## 第四轮修复（清除UI残留 + 全2/4禁用）

### Bug 1: 清除后样式仍然残留（多轮迭代）
- **现象**: 清除操作后，原来2和4方块的视觉样式（颜色、位置）仍残留在棋盘上
- **根因**: `.tile` CSS 有 `transition: left/top 0.12s cubic-bezier(...)` 过渡属性。浏览器移除DOM元素时，CSS过渡引擎可能"粘住"旧渲染帧，`innerHTML=''` / `remove()` / 强制重排均无法消除视觉残留
- **最终修复（核弹级方案）**: `executeClear()` 改用**隐藏→清空→重建→显示**五步流程：
  1. `tl.style.display = 'none'` — 先隐藏整个tile-layer（瞬间消灭所有视觉）
  2. `tl.innerHTML = ''` — 清空内容
  3. `addRandomTile()` — 数据层补上新方块
  4. `syncBoard()` — 从干净状态重建全部DOM
  5. `tl.style.display = ''` — 恢复显示（此时只有新元素可见）
- 缓存版本号升级至 `app.js?v=1.2.0`

### Bug 2: 全2和4时清除按钮不灰色
- **根因**: `allTilesAreTwoOrFour()` 检查原来只写在 `updateAbilityButtons()` 的 `cost` 分支内部，free 和 limit模式下完全不会执行这个检查
- **修复**: 将清除按钮的两个特殊检查（全2/4 + 无可清除方块）**提升到模式判断之前**，作为所有模式通用的前置检查，用 `return` 提前退出
